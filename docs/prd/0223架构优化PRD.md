# 智能体中心（DeciGro Center）架构优化 PRD：联邦制有限涌现与强合规改造

## 1. 背景与目标 (Background & Objectives)

### 1.1 业务背景

当前系统（`ifc-ai-decigro-center`）采用大模型结合 LangGraph 构建了智能体执行引擎（`ai-engine`）。在初版设计中，`planner_node` 赋予了大模型较高的自主规划能力（灵活的智能涌现）。然而，在券商等强监管的金融场景下，高度的自主性意味着不可控的业务风险（如幻觉导致违规调仓、越权查阅数据、给出违规投资建议等）。

### 1.2 核心目标

将系统从“大模型自主规划的黑盒”改造为**“分层路由 + 有限智能涌现的灰盒”**。
通过在数据模型和图执行引擎层面引入严格的层级划分与权限绑定，实现**“用代码画定轨道，用大模型驱动引擎”**，确保系统在券商场景100%合规落地。

### 1.3 核心原则

1. **收敛智能边界**：剥夺大模型在全局业务流程上的“发明权”。大模型的智能仅用于：意图识别、路由选择（分发）、以及在既定轨道内的参数提取（Slot Filling）。
2. **物理级风险隔离**：将全能型的 Agent 拆分为专职的 Agent 集群。每个具体的执行任务都在一个“权限沙箱”中运行，没有被硬编码授权的工具，大模型在物理层面绝对无法调用。
3. **强合规熔断**：高风险操作不仅需要预设轨道，还必须切断自动化闭环，强制引入人机协同（Human-In-The-Loop, HITL）。

### 1.4 技术要求

LangChain1.2 及以上版本

## 2. 为什么这样设计？(The "Why" - Core Architecture Evolution)

为了彻底根除大模型的发散性幻觉，我们采用**分层路由（Hierarchical Routing / Supervisor-Worker）**模式：

1. **收敛智能边界**：剥夺大模型在全局业务流程上的“发明权”。大模型的智能仅用于：意图识别、路由选择（分发）、以及在既定轨道内的参数提取（Slot Filling）。
2. **物理级风险隔离**：将全能型的 Agent 拆分为专职的 Agent 集群。每个具体的执行任务都在一个“权限沙箱”中运行，没有被硬编码授权的工具，大模型在物理层面绝对无法调用。
3. **强合规熔断**：高风险操作不仅需要预设轨道，还必须切断自动化闭环，强制引入人机协同（Human-In-The-Loop, HITL）。

## 3. 总体设计思路 (The "How" - High-level Design)

系统架构分为两部分协同改造：业务总线层（`bus-kernel`）负责静态权限与拓扑关系配置,即后台管理绑定关系，AI 引擎层（`ai-engine`）负责动态的层级状态机流转。

### 3.1 核心概念重塑：Agent Card 分类

`AgentCard` 拆分为 规划智能体Card和执行智能体Card 并进行分别管理
将系统原有的单一 `AgentCard` 概念进行分类升级，形成三级递进结构：

- **ROUTER (全局路由器)**：原有的全局规划者。不再生成步骤，只负责根据 UserContext 和当前对话，将其分发给最合适的 PLANNER。
- **PLANNER AGENT (业务领域规划者)**：例如“理财专家”、“开户向导”。它管理一个垂直领域的业务。它**绑定了 N 个 EXECUTE AGENT**。PLANNER AGENT是业务的起点，除了闲聊以外，涉及到相关业务的，都必须从这里开始，不能越级调用，核心思想是“如果没有对应的业务规划者，那该业务本系统就不支持”，需要明确告知用户。
- **EXECUTE AGENT (具体任务执行者)**：例如“持仓查询员”、“风险测评员”。它只负责执行单一明确的任务。它**绑定了有限的 M 个 TOOL CARD**。在 M 个 TOOL CARD中进行有限的智能涌现。

### 3.2 强合规机制：Tool Card 风险分级

Tool Card 进一步加强监管，目前仅分为PUBLIC和PROTECTED，PROTECTED只有被Agent绑定时才生效

## 5. 验收标准与检查清单 (Acceptance Criteria / Verification)

开发完成后，通过以下标准检查系统是否达到“有限智能涌现”与“强合规”目标：

- [ ] **越权调用测试**：模拟大模型发生幻觉，强制在其 Prompt 中要求调用当前 Execute Agent 未绑定的工具。**预期结果**：系统在工具组装层直接抛出权限异常或找不到工具，绝对不能发生实际的 API 请求。
- [ ] **边界涌现测试**：输入一个模糊的复合意图（如“我想看看行情顺便改个密码”）。**预期结果**：Router 明确选择一个 Planner（如先选理财Planner），在 Planner 内部调度时，只能生成预设范围内的话术或槽位提取，无法“发明”一个包含查行情+改密码的连贯非标新动作。
- [ ] **审计快照测试**：检查 Elasticsearch (`AiChatTraceIndex`) 中的日志。**预期结果**：能清晰看到任务是从哪个 Planner 下发到了哪个 Executor，且调用的入参中没有客户敏感信息（PII 已脱敏）。
